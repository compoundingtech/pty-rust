## 1. WIRE PROTOCOL (per-session Unix socket `<PTY_ROOT>/<name>.sock`)

### 1.1 Framing

- Packet = `[type: uint8][length: uint32BE][payload: length bytes]`; `HEADER_SIZE = 5` (`src/protocol.ts:23-24`; `encodePacket` `:45-50`).
- `MAX_PACKET_LENGTH = 32 * 1024 * 1024` (`:30`). A declared length above it makes `PacketReader.feed` throw `PacketTooLargeError` (`name: "PacketTooLargeError"`, `declaredLength`, message `` Packet length ${n} exceeds maximum ${MAX} ``) and *poison* (empty) the reader buffer (`:34-43`, `:141-146`).
- `PacketReader.feed(chunk)` appends, then loops: needs ≥ 5 bytes; if the payload is incomplete it stops and retains the partial bytes; each payload is copied out (`:130-158`). Unknown type bytes are parsed and delivered like any other; every consumer `switch`es and silently ignores unknown types (server `src/server.ts:929-1051`; CLI `src/client.ts:642-657`; `SessionConnection` `src/connection.ts:262-288`; testing lib `src/testing/session.ts:431-455`). This is the versioning model: unknown bounded packets are ignored (`docs/vrs/spec.md:78-79`, `docs/client.md:550-553`).
- On `PacketTooLargeError`: server logs `` Rejected client packet: ${msg} `` and destroys the socket (`src/server.ts:918-928`); CLI clients log `` pty client: dropping connection — ${msg} `` and destroy (`src/client.ts:120-124`, `:361-365`, `:589-594`); `SessionConnection` destroys silently (`src/connection.ts:258-261`); `peekScreen` rejects (`:401-405`).

Pinned by `tests/protocol.test.ts`: DATA/ATTACH/DETACH/RESIZE/EXIT/SCREEN/STATUS/GEOMETRY round-trips (`:26-101`, `:210-217`, `:288-297`); ATTACH(24,80) byte-equals `encodePacket(1, [0,24,0,80])` (`:49-59`); three packets in one chunk parse in order (`:105-118`); a packet split at [0,3),[3,8),[8,end) yields 0,0,1 packets (`:120-135`); split exactly after the 5-byte header (`:137-149`); empty payload (`:151-159`); 100 000-byte payload intact (`:161-169`); handcrafted type 99 len 3 passes through with `type === 99` (`:171-184`); `decodeSize` on 2-byte/empty payload → `{24,80}` (`:188-198`); `decodeExit` on 2-byte/empty → `-1` (`:200-206`); declared length `MAX+1` or `0xffffffff` throws on the header alone (`:219-236`); after the throw, a valid `encodeData("hi")` parses as one packet (buffer cleared) (`:238-250`); STATUS JSON round-trip including `connections[{role:"writable",rows,cols,lastRequestSequence:1,constrains:{rows:true,cols:true}}]` (`:262-286`); a client that only handles DATA skips a leading GEOMETRY frame and still sees `"after-unknown"` (`:299-313`); a legacy STATUS body without `connections` decodes with `clients` deep-equal `{total:2,attached:2,readOnly:0}` and `connections === undefined` (`:315-345`). `tests/integration.test.ts:1477-1543`: truncated ATTACH (2-byte) ignored and a later valid ATTACH works; 1-byte RESIZE ignored; unknown type 99 ignored.

### 1.2 Message types (`src/protocol.ts:3-14`)

| value | name | direction | payload |
|---|---|---|---|
| 0 | DATA | both | raw bytes; `encodeData` encodes a JS string as UTF-8 (`:52-54`); the server decodes inbound DATA with `payload.toString()` (UTF-8) before writing to the pty (`src/server.ts:1024`) |
| 1 | ATTACH | C→S | 4 bytes `rows u16BE @0, cols u16BE @2` (`:56-61`) |
| 2 | DETACH | C→S; machine-stream→caller | empty (`:63-65`) |
| 3 | RESIZE | C→S | 4 bytes `rows u16BE, cols u16BE` (`:67-72`) |
| 4 | EXIT | S→C | 4 bytes `int32BE` exit code (`:81-85`) |
| 5 | SCREEN | S→C | UTF-8 string screen replay (`:94-96`) |
| 6 | PEEK | C→S | 1 byte flags: bit0 plain, bit1 full scrollback (`:87-92`) |
| 7 | STATUS | C→S request: empty (`:98-100`); S→C response: UTF-8 JSON (`:102-104`) |
| 8, 9 | reserved | — | "reserved for independent protocol extensions" (`:12`) |
| 10 | GEOMETRY | S→C | 4 bytes `rows u16BE, cols u16BE` (`:74-79`) |

Decoders with legacy fallbacks (`docs/vrs/spec.md:171`): `decodeSize` → `{rows:24, cols:80}` when < 4 bytes (`:106-114`); `decodeGeometry` = `decodeSize` (`:116-118`); `decodeExit` → `-1` when < 4 bytes (`:120-125`).

### 1.3 Server per-connection state and inbound handling (`src/server.ts:75-90`, `:904-1063`)

Each accepted socket gets `Client { socket, reader, rows: terminal.rows, cols: terminal.cols, readonly:false, attachSeq:0, initialScreenPhase:"live", initialScreenGeneration:0, postCutPackets:[] }` (`:905-916`). `attachSeq === 0 && !readonly` is the **command role** (`pty send`, `pty stats`). Roles replace rather than accumulate (`docs/vrs/spec.md:97-107`).

- **ATTACH** (`:931-996`): payload < 4 bytes → ignored (no role/geometry/generation change) (`:932`). Else: `sizeMatched = (rows,cols) == terminal` computed before negotiation (`:936-937`); `readonly=false`, rows/cols stored, `attachSeq = ++attachCounter`, phase `"settling"`, `postCutPackets=[]`, `initialScreenGeneration++` (`:938-944`); `negotiateSize()`; if it did not resize, `GEOMETRY(terminal.rows, terminal.cols)` is written to this socket immediately (`:945-948`) (if it did resize, `broadcastGeometry` already sent GEOMETRY to every attached/readonly socket including this one, `:1174`, `:1183-1190`); best-effort `metadata.lastAttachAt = now` under lock with `expectedGeneration` (`:951-956`); SCREEN cut scheduled: if child alive and (`resized` or `now − lastResizeTime < 80 ms`) delay `80` ms (`REDRAW_SETTLE_MS`) or the remainder, else immediate; after exit always immediate (`:979-994`). Screen = `getModePrefix(true) + serialize.serialize()` (full scrollback + alt buffer + modes) (`:962`). After the SCREEN goes live, if `!exited && !sizeMatched` → `nudgeRedraw()` (pty and xterm resized to `cols−1` then back, `:974`, `:1195-1202`).
- **PEEK** (`:998-1020`): `readonly=true`, phase settling, generation++, `negotiateSize()` (a formerly writable socket drops out of the geometry set), GEOMETRY if no resize; `flags = payload[0] ?? 0`, `plain = flags&1`, `full = flags&2`; screen = plain ? (`full ? getFullPlainScreen() : getPlainScreen()`) : `getModePrefix()` (no alt-screen prefix) + `serialize.serialize(full ? undefined : {scrollback: 0})` (`:1011-1018`).
- **DATA** (`:1022-1027`): written to the pty only if `!exited && !readonly`; command-role sockets may write.
- **RESIZE** (`:1029-1038`): honoured only if `!readonly && attachSeq > 0 && payload ≥ 4`; stores rows/cols, `attachSeq = ++attachCounter`, `negotiateSize()`.
- **DETACH** (`:1040-1043`): `socket.end()`.
- **STATUS** (`:1045-1049`): reply `STATUS(JSON.stringify(collectStats()))`, any role.
- `close`/`error` (`:1054-1062`): remove client, `negotiateSize()`.

### 1.4 Attach handshake / synchronization generation (`src/server.ts:1213-1267`)

`beginInitialScreenCut(client, generation, getScreen, onLive)`: if the socket is destroyed or `client.initialScreenGeneration !== generation` (a newer ATTACH/PEEK superseded it) → return without sending (`:1219-1222`). Phase → `"cutting"`; `terminal.write("", cb)` is the ordered parser marker (`:1224-1228`). In `cb`: re-check; take `postCutPackets`; write `SCREEN(getScreen())`; phase `"live"`; write queued DATA/EXIT in order; if `exited` and no EXIT was queued, synthesize `EXIT(exitCode)`; `onLive()` (`:1229-1252`).

`broadcast(type, packet)` (`:1255-1267`): `"settling"` clients are skipped (their bytes land in the upcoming SCREEN), `"cutting"` clients get the packet queued, `"live"` clients get it written. Only DATA/EXIT use `broadcast`; GEOMETRY uses `broadcastGeometry` to sockets with `attachSeq > 0 || readonly` (`:1183-1190`).

Public order per generation: `GEOMETRY -> SCREEN -> DATA* -> EXIT?` (`docs/vrs/spec.md:81-95`, `docs/client.md:555-569`).

Pinned by `tests/integration.test.ts` (with the 80 ms settle timer faked, `:557-561`, `:651-655`): a new attacher's sequence is exactly `[GEOMETRY, SCREEN]` and live DATA produced during sync is folded into SCREEN (contains `during-initial-sync`) (`:423-471`); pre-cut DATA still queued in the parser is not lost (`parser-backlog` in SCREEN+DATA) (`:473-529`); post-cut DATA before a post-cut EXIT: `[GEOMETRY, GEOMETRY(after RESIZE), SCREEN, DATA("post-cut-data"), EXIT(7)]`, exactly one EXIT (`:531-616`); EXIT before the cut, DATA after: `[GEOMETRY, SCREEN, DATA("final-post-cut-data"), EXIT(7)]` (`:618-699`); child exits during sync: `[GEOMETRY, GEOMETRY, SCREEN, EXIT(7)]` (`:701-762`); a second ATTACH while the first is pending supersedes it: `[GEOMETRY, GEOMETRY, SCREEN]` (`:764-800`); PEEK while ATTACH pending cancels the attach sync and the peeker then receives live DATA (`:802-852`). `tests/exit-event-race.test.ts:82-136`: exactly one `session_exit` (with numeric `exitCode`) and exactly one `session_start` on disk after exit or SIGTERM.

### 1.5 Effective geometry (`src/server.ts:1158-1181`)

`negotiateSize()`: over clients with `!readonly && attachSeq > 0`, `rows = min(rows)` and `cols = min(cols)` independently; if both > 0 and either differs: `terminal.resize(cols, rows)`, `broadcastGeometry(rows, cols)`, `ptyProcess.resize(cols, rows)`, `lastResizeTime = now`, return true. Zero writable clients → nothing changes (last geometry sticks). GEOMETRY is broadcast before the pty is resized, so it precedes any child output for the new size.
